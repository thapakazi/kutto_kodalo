# Conventions

This is the only hand-maintained document in `docs/`. Everything under
`docs/reference/` is generated by `bin/shellrc-doc` — never edit it.

## Repository layout

```
shellrc              entry point; resolves its own path, sources everything below
lib/                 numbered, always loaded, in order. The compat layer.
modules/common/      portable — must work on macOS and Linux
modules/darwin/      macOS only
modules/linux/       Linux only
modules/local/       machine-specific, gitignored, never committed
completions/         zsh completion functions (_name)
bin/                 bootstrap, doctor, shellrc-doc
docs/reference/      GENERATED — do not edit
attic/               retired code, kept for history, never sourced
```

## Function documentation block

Every public function gets a doc block immediately above it. The generator reads
these; there is no separate doc source.

```sh
# @describe One-line summary, imperative mood. Wrap continuation lines with
#           leading whitespace like this.
# @usage    function_name <required> [optional]
# @example  function_name ~/some/file
# @requires jq docker
# @os       any
# @danger   Deletes files without further prompting.
function_name() {
    ...
}
```

| Tag         | Required | Meaning                                                   |
|-------------|----------|-----------------------------------------------------------|
| `@describe` | yes      | One-line summary. First sentence is used in the index.     |
| `@usage`    | yes      | Signature. `<>` required, `[]` optional.                   |
| `@example`  | no       | Repeatable. Real, runnable invocations.                    |
| `@requires` | no       | External commands. `a\|b` means "any one of".              |
| `@os`       | yes      | `any`, `darwin`, or `linux`.                               |
| `@danger`   | no       | Present on anything destructive. Rendered as a warning.    |
| `@see`      | no       | Related function names.                                    |
| `@complete` | no       | **Not implemented** — parsed by nothing. See below.        |

## Completion blocks — NOT IMPLEMENTED YET

> **Nothing in this section exists.** There is no `bin/shellrc-completions`, the
> `@complete` tag is not parsed by `bin/shellrc-doc`, and it produces no key in
> `docs/functions.json`. `completions/` currently holds two **hand-written** zsh
> files (`_shelp`, `_aws_ssm_session`).
>
> Do not add `@complete` tags expecting them to do anything, and do not delete
> the hand-written completions as stale generated output. This is the design
> agreed for the generator when it is built; it is recorded here so the shape is
> settled, not because it works today.

The intended design: completions are generated, not hand-written.
`bin/shellrc-completions` reads `docs/functions.json` and emits both zsh and
bash completers.

`@complete` maps each placeholder in `@usage` to a source of candidates:

```sh
# @usage    aws_ssm_get_param <app> <env> [suffix]
# @complete app:@aws_list_apps env:(development staging production) suffix:(env config)
aws_ssm_get_param() {
```

Placeholder names must match `@usage` exactly. Sources:

| Source            | Candidates from                                      |
|-------------------|------------------------------------------------------|
| `(a b c)`         | a fixed word list                                    |
| `@fn_name`        | a repo function that prints one candidate per line   |
| `!command …`      | a shell command that prints one candidate per line   |
| `:file`           | filenames                                            |
| `:dir`            | directories                                          |
| `:host`           | known SSH hosts                                      |
| `:pid`            | running processes                                    |

**Annotation is optional.** With no `@complete`, the generator infers from the
`@usage` placeholder name — `<file>`, `<path>`, `<dir>`, `<host>`, `<pid>`,
`<port>`, `<url>` all map to sensible defaults, and anything unrecognised falls
back to file completion. Annotate only where inference is wrong or a real word
list exists.

Dynamic sources (`@fn` / `!cmd`) are evaluated at completion time, not at load
time, and their output is cached in `$SHELLRC_CACHE` for the duration of the
shell. Never put a slow command behind one.

Each module file starts with a header:

```sh
# @module docker
# @summary Container helpers: inspection, cleanup, compose shortcuts.
```

Private helpers are prefixed `_` and are skipped by the generator.

**The definition must start at column 0, and the doc block must be the comment
lines immediately above it with no blank line between.** `bin/shellrc-doc`
anchors its matcher at column 0, so an indented definition — one wrapped in an
`if require ...; then` block, or moved by a reformat — is dropped from the docs
entirely. It warns when a documented function is indented; annotate deliberate
exceptions such as lazy-loading stubs with `# shellrc-doc: ignore`.

## Naming rules

1. **`<namespace>_<verb>_<noun>`**, lowercase, underscores only. No dots, no
   hyphens, never a leading digit — `2fa-fzf` is not a valid bash function name.
2. The namespace is the module: `aws_`, `docker_`, `git_`, `k8s_`.
   Cross-cutting primitives in `lib/` are exempt (`has`, `confirm`, `clip_copy`).
3. **Never shadow a real binary.** Not `ssh`, `emacs`, `uptime`, `claude`,
   `init`, `try`, `py`. Check with `command -v <name>` before choosing.
4. Verb first after the namespace: `aws_get_caller_identity`, not
   `aws_caller_identity_get`.
5. Short aliases are fine, but they are *aliases* onto a full name, defined at
   the bottom of the module in an explicit block. The long name is the API.

## Portability rules

1. Never call `pbcopy`, `xclip`, `xdg-open`, `sed -i`, `readlink -f`, or
   `base64 -w0` directly. Use `lib/30-compat.sh`: `clip_copy`, `clip_paste`,
   `os_open`, `sed_inplace`, `path_resolve`, `b64_encode`, `b64_decode`.
2. Guard every module on its dependencies at the top:
   ```sh
   require docker || return 0
   ```
   A module whose tools are absent defines nothing and stays silent. `doctor`
   reports what was skipped.
3. No hardcoded absolute paths to binaries. Resolve via PATH.
4. No version-pinned paths (`/opt/homebrew/Cellar/gnu-sed/4.9/...`).
5. Quote every expansion. `"$var"`, `"$@"`, `"${arr[@]}"`. Paths contain spaces —
   `~/Library/Application Support/` is on every Mac.
6. `local` every variable inside a function.
7. **Never use a zsh special parameter name as a local**, even in a file you
   think only bash will read. `local path=...` shadows zsh's `path` array, which
   is tied to `$PATH` — it empties `PATH` for the rest of that function and you
   get `cut: command not found` from a line that has nothing to do with PATH.

   The dangerous ones are **tied** to an uppercase environment variable, so
   shadowing them silently rewrites it:

   ```
   path  fpath  cdpath  manpath  mailpath  module_path  fignore
   ```

   `status` is read-only and errors loudly instead. These are special but
   harmless to shadow locally: `argv options commands functions aliases
   dirstack psvar prompt watch`.

   Use `target_path`, `rc`, `opts` instead. When unsure, check it:

   ```sh
   zsh -f -c 'print ${(t)NAME}'    # anything with "tied" or "special" is off limits
   ```

   Scope: this applies to `lib/` and `modules/`, which are sourced into zsh.
   Scripts under `bin/` run with a bash shebang and are exempt.
8. OS-specific code belongs in `modules/darwin/` or `modules/linux/`, not behind
   an `if` in `modules/common/`.

## Safety rules

1. **Nothing executes at source time** except variable assignment, function
   definition, and setting shell options. No network calls, no file writes, no
   `git clone`, no subshells that fork a process. Startup must stay under 100ms.

   Shell options (`setopt PROMPT_SUBST`, `bindkey`, `set -o vi`) ARE allowed —
   that is configuration, not work, and `modules/common/prompt.sh` depends on
   it. Forking a process is the line.
2. Never `exit` in a sourced file — it kills the user's interactive shell.
   Use `return`.
3. Destructive functions must call `confirm` and carry `@danger`.
4. Use `tmp_file` / `tmp_dir`, never a predictable `/tmp/name`.
5. Never write a secret to a file that outlives the function. Clean up with a
   trap.
6. No `curl | bash`. Download, show the user, then execute deliberately.

## Verifying

```sh
bin/doctor            # what's missing on this machine
bin/shellrc-doc       # regenerate docs/reference/
shellcheck -s bash lib/*.sh modules/*/*.sh
SHELLRC_DEBUG=1 zsh -i -c exit    # per-file load timing
```
